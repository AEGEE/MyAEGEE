# Subject Matter Expert (SME) Questionnaire

## AEGEE OMS Voting System Rewrite

## Purpose

This questionnaire is designed for AEGEE Judicial Committee (JC) members and other subject matter experts who understand AEGEE's organizational structure, statutory requirements, and business processes. Your expertise is crucial for defining the functional requirements and business rules for the new voting system.

### 1.2 Delegate Management

**Q1.2.1: What are the exact rules for delegate registration?**

- Maximum number of delegates per antenna: \_\_ (currently documented as 3)
- Registration deadline relative to Agora: \_\_ days/weeks before
- Can delegate substitutions be made after the deadline? Yes/No
- If yes, until when can substitutions be made?

**Answer:**

If an antenna is present, it should have between 1 and 3 delegates. People can be changed from visitor/envoy (or even with a new application) to delegate based on an approved exception to the Working Format of the Agora. This change does not have to linked automatically to that vote, but the JC should be able to change the participant type in the statutory module. This happens usually in the first day of the Agora but it can also be done later.

**Q1.2.2: How should delegate departures be handled?**

- Who can mark a delegate as departed? \***\*\*\*\*\***\_\_\_\_\***\*\*\*\*\***
- Is there a verification process for departures? Yes/No
- Can delegates return after being marked as departed? Yes/No
- If yes, what is the process for returning?

**Answer:**

JC can mark delegates as departured, so the voting division can be updated between possible left over delegates (or the antenna is not marked as present anymore, if there are no remaining delegates). This can also be reverted by JC. There is no formal proces for returning.

### 2.2 Amendment Process

**Q2.2.1: How should member-submitted amendments work?**

- Are member amendments immediately visible to all? Yes/No
- Do member amendments require JC approval before publication? Yes/No
- Can multiple amendments be submitted per proposal? Yes/No

**Answer:**
Member amendments are not immediately visible to all, but require JC approval. Multiple amendments can be submitted per proposal. During the prytanium it is also possible to amend amendments. The amendments should be sent to JC before the start of the prytanium that discusses the proposal, but live amendments can also be made during the prytanium. - What happens when amendments contradict each other?

**Answer:**

The proposer resolves conflicts, together with the support of JC. Amendments can be merged or combined. The JC and the proposer are responsible that accepted amendments do not contradict each other

## Section 4: Attendance and Real-time Features

### 4.1 Attendance Verification

**Q4.1.1: How should attendance be verified for different contexts?**

**During Agora plenary sessions:**

- [ ] Barcode scanning required for all votes
- [ ] Check-in at start of session sufficient
- [ ] Continuous presence verification
- [ ] Other: \***\*\*\*\*\***\_\_\_\_\***\*\*\*\*\***

**Pre/Post-Agora voting:**

- [ ] Same as plenary sessions
- [ ] Different verification method: \***\*\*\*\*\***\_\_\_\_\***\*\*\*\*\***
- [ ] No special verification required

**Answer:**

During Agora plenary sessions, there is check-in at the start of the session by scanning barcodes of delegates and envoys of Contact Antenna. They also have to check-out and check back in anytime they are leaving the plenary session (for instance to go to the bathroom).

For the Pre- and Post-Agora voting, there is nothing to measure attendance

**Q4.1.2: How should remote participation be handled?**

- Is remote voting allowed? Yes/No
- If yes, what verification is required for remote delegates?
- Are there limitations on remote participation?

**Answer:**

If you are marked as present, you can vote remotely from anywhere.

### 4.2 Real-time Updates and Transparency

**Q4.2.1: What voting information should be visible during voting?**

**To all delegates:**

- [ ] Real-time vote tallies
- [ ] Number of votes cast (without results)
- [ ] Their antenna's voting progress
- [ ] No real-time information

**To JC members/chairs:**

- [ ] Full real-time tallies
- [ ] Voting progress by antenna
- [ ] Individual delegate voting status
- [ ] Same as delegates

**To observers:**

- [ ] Same as delegates
- [ ] Limited public information

**Answer:**

For delegates, you should be able to see number of votes cast and vote result from your Antenna.

For JC members, a full real-time tally of all votes.

For observers (inlcudig visitors) no information during the voting process, only after the results are published by JC

**Q4.2.2: Should delegates see how their antenna colleagues voted?**

- What privacy protections are needed?

No privacy protections are needed, delegates should be able to see the antenna vote distribution in real-time.
