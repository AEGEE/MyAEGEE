## Core Documentation Guidelines

- Refer to CIA (document with internal rules and regulations) where applicable
- Write out processes/workflows separate from pages, but do add references to those two
- Add MoSCoW classification for all functionality. Must haves need to be fixed with the first released version, Should and Could are for later
- Add personas and who can see/do what
- Provide examples with the pages and processes/workflows so it is clear what data is displayed or validation requirements etc
- Also mark which microservice deals with this and what data is exchanged from core/statutory. For the frontend pages also mark which data we are requesting and in which microservice it is stored
- The documentation will be reviewed by SMEs, which are not technical but know everything from the process. Do feel free to set up technical implementation notes linked to the requirements etc in different documents that the developers can take a look at
- Feel free to use as many Markdown documents as you need, and use mermaid to graph things
